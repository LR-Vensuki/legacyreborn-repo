# Cydia-репозиторий в стиле iOS 6

Репозиторий для Cydia, Sileo, Zebra и Installer с сайтом в стиле iOS 6 и классической Cydia:
полосатый фон, сгруппированные таблицы, синий навбар, глянцевые кнопки.

Опубликовать твик можно одной командой из Theos: `make publish`. Собрать и выложить репозиторий можно двумя способами, выбор задаёт `"deploy"` в `config.json`:

- **`"github"`** (по умолчанию). Пакеты коммитятся в этот git-репозиторий, GitHub Actions собирает репозиторий и выкладывает его на GitHub Pages под вашим доменом. Это бесплатно, а HTTP для iOS 6 работает.
- **`"hosting"`**. Пакеты отправляются на обычный хостинг с PHP, и хостинг собирает репозиторий сам. Бесплатные хостинги на платформе iFastNet (InfinityFree, ByetHost и т.п.) **не подходят**: они пускают только браузеры, и Cydia к ним не подключится.

В обоих случаях сборку делает один и тот же PHP-сборщик из `server/`.

## Установка: GitHub Pages со своим доменом

1. В `config.json` укажите `name`, `description` и `url`, например `http://repo.example.com/`. Пишите именно `http://`, иначе iOS 6 не подключится.
2. Один раз укажите git, кто автор коммитов (если ещё не делали):

   ```bash
   git config --global user.name "Ваше имя"
   ```

   ```bash
   git config --global user.email "ID+логин@users.noreply.github.com"
   ```

   Адрес вида `…@users.noreply.github.com` есть на github.com/settings/emails. Он скрывает ваш настоящий email.
3. Подготовьте git-репозиторий (будет создан первый коммит):

   ```bash
   python3 tools/repo.py setup
   ```

4. На github.com создайте **пустой публичный** репозиторий, без README. Бесплатный GitHub Pages работает только с публичными репозиториями.
5. Подключите его:

   ```bash
   python3 tools/repo.py setup --remote https://github.com/ЛОГИН/ИМЯ.git
   ```

6. Отправьте проект:

   ```bash
   git push -u origin main
   ```

   GitHub спросит логин и вместо пароля токен: Settings → Developer settings → Personal access tokens. Токену нужны права **repo** и **workflow**. Без `workflow` GitHub не примет файл `.github/workflows/deploy.yml`.
7. В репозитории на GitHub: **Settings → Pages → Source: GitHub Actions**. Затем пересоберите (первая сборка могла не пройти, пока Pages был выключен):

   ```bash
   python3 tools/repo.py rebuild
   ```

8. В DNS домена (например, в Cloudflare) удалите старые записи поддомена (`A` или `NS`, которые смотрят на прежний хостинг) и добавьте:
   `CNAME  repo  →  ЛОГИН.github.io`, режим **DNS only** (серое облако). Если оставить проксирование Cloudflare, он может включить HTTPS и сломать iOS 6.
9. **Settings → Pages → Custom domain**: впишите ваш домен (`repo.example.com`) и нажмите Save. Когда проверка DNS пройдёт, **снимите галочку «Enforce HTTPS»**: так сайт откроется и по `http://` (для iOS 6), и по `https://`.
10. Проверьте:

    ```bash
    python3 tools/repo.py status
    ```

    Должно быть написано «сайт работает».

## Установка: свой PHP-хостинг

1. В `config.json` добавьте `"deploy": "hosting"` и укажите `url` сайта.
2. Создайте ключ публикации:

   ```bash
   python3 tools/repo.py setup
   ```

3. По FTP загрузите **содержимое** папки `server/` в корень сайта. Нужно всё, вместе со скрытыми `.htaccess` и `.user.ini` и с `repo/secret.php`. Стандартную заглушку хостинга (`index.php`, `index.htm`) из корня удалите.
4. Залейте настройки и оформление и соберите сайт:

   ```bash
   python3 tools/repo.py sync
   ```

Нужен PHP 7.4 или новее. Python на хостинге не нужен.

## Публикация твиков из Theos

Добавьте в `Makefile` твика (после строки `include ...tweak.mk`):

```make
CYDIA_REPO = $(HOME)/Theos-Projects/cydia-repo

publish:: package
	@python3 $(CYDIA_REPO)/tools/repo.py publish $(THEOS_PROJECT_DIR) $(if $(MSG),-m "$(MSG)")

depiction::
	@python3 $(CYDIA_REPO)/tools/repo.py publish $(THEOS_PROJECT_DIR) --depiction-only
```

Новый твик или обновление публикуется одной командой:

```bash
make publish FINALPACKAGE=1 MSG="Исправлен вылет на iOS 6.1.3"
```

Что при этом происходит:

1. Theos собирает `.deb`.
2. Если пакет сжат xz или zstd, он перепаковывается в gzip: старый dpkg на iOS 6 не умеет xz, а PHP-сборщик читает только gzip. Содержимое пакета не меняется.
3. Строка из `MSG` дописывается в `depiction/changelog.md` проекта.
4. Пакет и описание попадают в репозиторий. В режиме GitHub это коммит и push, на хостинге это загрузка через `publish.php`. Повторная публикация той же версии ничего не делает.
5. Репозиторий пересобирается. На GitHub это занимает 1–2 минуты (ход сборки видно на вкладке Actions), на хостинге несколько секунд. После этого пользователю достаточно нажать «Обновить» в Cydia.

Чтобы вышло **обновление**, увеличьте `Version` в `control` и снова выполните `make publish`. Старые версии остаются, чтобы из Cydia можно было откатиться. Удалить их можно флагом `--replace` или командой `remove`.

Сборки без `FINALPACKAGE=1` (с `+debug` в версии) не публикуются, чтобы случайно не выложить отладочную версию.

`make depiction` публикует только описание и скриншоты, без пересборки пакета.

## Описание пакета: папка `depiction/` в Theos-проекте

Папка необязательна. Без неё описание и разработчик берутся из `control` (`Description`, `Author`), а совместимость вычисляется из `Depends: firmware (>= 5.0)`. Шаблон папки лежит в [examples/depiction](examples/depiction).

| Файл | Назначение |
|---|---|
| `description.md` | Полное описание в Markdown (абзацы, списки, заголовки, **жирный**, *курсив*, ссылки). `description.html` — то же, но готовым HTML. |
| `changelog.md` | История версий: `## 1.0.1 (2026-10-02)` и пункты под заголовком. `make publish MSG="..."` дописывает её сам. |
| `meta.json` | Переопределения, см. ниже. |
| `icon.png` | Иконка пакета, квадрат от 120×120 (png/jpg/gif). |
| `screenshots/` | Скриншоты, идут по порядку имён: `01.png`, `02.png`… |
| `banner.png` | Широкий баннер ~1052×592: шапка в Sileo и баннер в «Рекомендуемых». |

`meta.json`:

| Ключ | Пример | Что делает |
|---|---|---|
| `name` | `"My Tweak"` | Отображаемое имя. |
| `tagline` | `"Тени для иконок"` | Короткое описание в списке. |
| `author` | `"Your Name"` | Разработчик. |
| `compatible` | `"iOS 5.0 – 6.1.6"` | Строка «Совместимость». |
| `featured` | `true` | Показывать в «Рекомендуемых». |
| `hidden` | `true` | Не показывать в списке на сайте. Пакет при этом остаётся доступен для установки и скачивания, так что это **не** закрытая бета. |
| `price` | `""` | Цена; по умолчанию «Бесплатно». |
| `tint` | `"#2463de"` | Цвет акцента в Sileo. |
| `links` | `[{"title": "GitHub", "url": "https://…"}]` | Ссылки на странице пакета. |

## Команды `tools/repo.py`

| Команда | Что делает |
|---|---|
| `setup` | GitHub: создаёт git-репозиторий и первый коммит; `--remote URL` подключает репозиторий на GitHub. Хостинг: создаёт ключ публикации (`--new-key` меняет его). |
| `status` | Показывает, что отправлено, и проверяет, отвечает ли сайт так, как нужно Cydia. |
| `publish ФАЙЛ.deb\|ПАПКА_THEOS` | Публикует пакет. Флаги: `-m "строка"` (changelog), `--replace` (удалить старые версии), `--depiction ПАПКА`, `--depiction-only`, `--no-build` (GitHub: только коммит, без отправки), `--allow-debug`. |
| `sync` | Публикует изменения `config.json`, иконки и `theme/`. |
| `remove ID [-V ВЕРСИЯ] [-y]` | Удаляет пакет или одну его версию (с подтверждением). |
| `rebuild` | Пересобирает сайт. На GitHub заодно отправляет всё, что ещё не отправлено. |

## Безопасность

**GitHub Pages:**

- Опубликовать что-то может только тот, у кого есть право push в ваш репозиторий. Включите на аккаунте GitHub двухфакторную аутентификацию.
- Чужие pull request ничего не выкладывают: сборка запускается только на push в `main`.
- На GitHub Pages не выполняется никакой код, это только статические файлы. В опубликованный сайт попадают только готовые страницы и `.deb`; исходники и PHP-сборщик не попадают.
- В git не попадают ключ хостинга (`publish.json`, `server/repo/secret.php`) и любые архивы (`*.zip` и т.п.): в архиве легко случайно унести ключ.

**PHP-хостинг:**

- На сайте нет админки и формы входа. Публиковать можно только через `publish.php`, каждый запрос подписан ключом из `secret.php` (HMAC-SHA256).
- Сам ключ по сети не передаётся. Подделать, изменить или повторить запрос нельзя: в подписи есть метка времени (±5 минут) и одноразовый номер.
- Через `publish.php` нельзя загрузить код: только `.deb`, картинки и `.md`/`.json`/`.css`/`.js`, и только в отведённые папки. Служебная папка `repo/` закрыта для браузера.
- Если ключ утёк, выполните `setup --new-key` и перезалейте `server/repo/secret.php`.

**В обоих случаях** файлы `.deb` и описания публичны, так устроен любой Cydia-репозиторий. Пакеты для iOS 6 скачиваются по HTTP без шифрования, как во всех легаси-репозиториях.

## iOS 6 и HTTPS

Старые iOS часто не могут подключиться к современным HTTPS-сайтам: на них нет новых корневых сертификатов и поддерживаются только старые шифры. Поэтому:

- в `config.json` → `url` пишите `http://`;
- на GitHub Pages снимите «Enforce HTTPS»; на хостинге не включайте редирект на https;
- в Cloudflare держите запись в режиме **DNS only** (серое облако) и не включайте «Always Use HTTPS».

`python3 tools/repo.py status` сам предупредит, если `http://` перенаправляется на `https://`.

## Если что-то не так

| Сообщение | Что делать |
|---|---|
| «git не знает автора коммитов» | Выполните две команды `git config --global ...` из шага 2 установки. |
| «git push не прошёл» | Нужен токен с правами `repo` и `workflow` (или SSH-ключ). Коммит сохранён, после исправления повторите команду. |
| Сборка на вкладке Actions падает на шаге deploy | Не включён Pages: Settings → Pages → Source: GitHub Actions, затем `repo.py rebuild`. |
| `status`: «всё ещё отвечает проверкой InfinityFree» | DNS ещё не переключён или не обновился (обычно до 30 минут). |
| `status`: «http перенаправляется на https» | Снимите «Enforce HTTPS» в Settings → Pages. |
| «JavaScript-проверку на робота» (хостинг) | Хостинг на платформе iFastNet пускает только браузеры. Нужен другой хостинг или GitHub Pages. |
| `bad signature` (хостинг) | `secret.php` на хостинге не совпадает с `publish.json`: перезалейте `server/repo/secret.php`. |
| `request expired` (хостинг) | Часы на компьютере расходятся с реальным временем больше чем на 5 минут. |

## config.json

| Ключ | По умолчанию | Описание |
|---|---|---|
| `name` | `"My Repo"` | Название репозитория. |
| `description` | `""` | Описание под названием и в `Release`. |
| `url` | — | Адрес репозитория со слэшем на конце. |
| `deploy` | `"github"` | Как публиковать: `"github"` или `"hosting"`. |
| `language` | `"en"` | Язык сайта: `ru` или `en`. |
| `maintainer` | `""` | `Имя <email>`; подставляется, если в пакете нет `Maintainer`. |
| `managers` | все | Кнопки добавления: `cydia`, `sileo`, `zebra`, `installer`. |
| `links` | `[]` | Ссылки внизу главной: `[{"title": "...", "url": "..."}]`. |
| `footer` | `""` | Текст внизу главной (можно `**жирный**` и `[ссылки](https://…)`). |
| `search` | `"auto"` | Строка поиска: `true`, `false` или `"auto"` (появляется, когда пакетов больше 5). |
| `keep_old_versions` | `true` | Держать старые версии в `Packages` для отката. |
| `legacy_checks` | `true` | Предупреждать о xz/zstd в пакетах для `iphoneos-arm`. |
| `tint` | `"#2463de"` | Цвет акцента в Sileo по умолчанию. |
| `origin`, `label`, `suite`, `codename`, `version`, `architectures` | | Поля `Release` (обычно трогать не нужно). |

## Структура

```
config.json            настройки репозитория
assets/CydiaIcon.png   иконка репозитория
theme/                 оформление: style.css, app.js, картинки
debs/                  пакеты (GitHub; на хостинге они лежат на сервере)
packages/<id>/         описания пакетов (GitHub; заполняется из depiction/ при publish)
server/                PHP-сборщик; на хостинг загружается целиком один раз
.github/workflows/     сборка и выкладка на GitHub Pages
tools/repo.py          публикация с компьютера (Python 3.8+, без зависимостей)
examples/depiction/    шаблон папки описания для Theos-проекта
```

Собранный сайт содержит `index.html`, `Packages`, `Packages.gz` (и `.bz2`, если в PHP есть bz2), `Release`, `CydiaIcon.png`, `debs/`, `depictions/<id>/` (страница пакета, история версий, `sileo.json`), `assets/`, `packages.json` и `404.html`.

## Оформление

Стили лежат в `theme/style.css`. После правки выполните `python3 tools/repo.py sync`. Если правите CSS, учитывайте старый WebKit в Cydia на iOS 6: не используйте flexbox, grid, CSS-переменные и `calc()`, а градиенты пишите и в старом `-webkit-gradient`, и в новом синтаксисе.
